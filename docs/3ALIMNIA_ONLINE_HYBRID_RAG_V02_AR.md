# 3alimnIA — Online-First Hybrid RAG V0.2

**تاريخ:** 13 نوفمبر 2026
**المصدر:** `qai_platform_ (11)(1).zip` / طبقة V0.1
**الحالة:** برمجية أولية مُختبرة بمحاكاة واعتمادًا على وظائف المشروع. **لم تُنفَّذ استدعاءات Gemini/Groq حقيقية، ولا اختبار متصفح شامل، ولا اختبار نشر مؤسسي.**

## 1) هدف الإصدار ولماذا ليس مجرد "RAG"

نواصل استخدام Streamlit وGroq/Gemini عبر الإنترنت. أضيفت طبقة تحقق وحوكمة للأدلة تتفادى تسوية المصادر المصنفة آليًا بالمصادر التي أجازها الأستاذ. تتعامل الطبقة مع المراجع التي يرفعها الأستاذ على أنها بيانات لا تعليمات، وتقيّد الاسترجاع بالحساب والمشروع، وتفرض موافقة منفصلة على إرسال البيانات إلى خدمات الذكاء الاصطناعي. لا يفترض الإصدار أن أي نص يستشهد بمصدر هو بالضرورة صحيح.

## 2) ما اكتمل بالفعل

1. `online_embeddings.py`: عميل Gemini `gemini-embedding-001` على نقطة نهاية Google الرسمية الثابتة HTTPS، متجهات 768، نوعا `RETRIEVAL_DOCUMENT` و`RETRIEVAL_QUERY`، مهلة وحدود طلب، ورسائل فشل لا تكشف المفتاح أو المحتوى. يحتاج مفتاحًا فعليًا، ولم يختبر Live في هذه البيئة.
2. `hybrid_rag.py`: فهرس SQLite FTS5 مع دمج اختياري للبحث الدلالي بطريقة Reciprocal Rank Fusion، أولوية وثائق الأستاذ على الوثائق الخارجية، مراجعة بشرية، معلومات مصدر وببليوغرافيا وDOI كبيانات وصفية، ترحيل قاعدة V0.1، ومعرف استشهاد دقيق من النمط `[RAGXXXXXXXXXXXX_P2_C3]` يحدد المصدر والصفحة والمقطع.
3. **موافقات منفصلة:** (أ) حق فهرسة الوثيقة على خادم Streamlit؛ (ب) السماح بإرسال مقاطعها إلى Gemini Embeddings؛ (ج) السماح بإرسال مقتطفاتها إلى نموذج توليد سحابي. الحالتان (ب) و(ج) لا تُمنحان افتراضيًا. يمكن سحب إذن التوليد وإلغاء استخدام embeddings مستقبلًا؛ لكن لا يمكن استرجاع ما أُرسل سابقًا إلى خدمة خارجية.
4. `rag_grounding.py`: تدقيق مبدئي لربط الاستشهاد بالمقطع، وكشف المعرّفات غير المعروفة والمقاطع التي قد تكون غير موثقة. **ليس نموذج استلزام دلالي ولا دليلًا على الصواب العلمي.**
5. `educational_builder.py`: إدراج المراجع المسموح بها للتوليد في البرومبتات حسب مرحلة إنشاء المحتوى، وتمييز النتائج لحاجة مراجعة الأستاذ بدل التقدم التلقائي عند وجود مقتطفات RAG أو تعذّر استرجاعها.
6. `lesson_block_generation_engine.py`: استشهادات مخصصة بالمقطع مع تدقيق محفوظ ضمن بيانات التقييم وتفعيل مراجعة الأستاذ.
7. `teacher_studio.py`: واجهة ثلاثية اللغة لرفع الملفات وتدوين بيانات المصادر واعتمادها وإدارة موافقات السحابة وتجربة الاسترجاع وعرض المعرف والصفحة. توضح الواجهة أن المصادر المصنفة آليًا ليست معتمدة علميًا من الأستاذ.
8. `benchmarks/`: قالب Gold للاسترجاع وقالب تحكيم بشري للادعاءات، وسكربت مبدئي لقياس Recall@K وnDCG@K دون اختلاق بيانات.

## 3) مسار العمل الجديد

```text
Teacher login + saved project (ownership checked by current platform)
  -> Upload allowed PDF/DOCX/TXT/MD (20 MiB max)
  -> Optional bibliographic label / HTTPS DOI or reference / rights note
  -> Initial indexing as DRAFT (no generation permitted)
  -> Teacher approval (separate from automatic source scoring)
  -> Optional explicit consent for cloud generation and/or Gemini Embeddings
  -> Approved + authorized text retrieved under owner/project scope
     -> FTS5 ranked lexical matches
     -> Gemini 001 semantic matches, when authorized and configured
     -> RRF + hard preference for teacher-provided sources
  -> Chunk references [RAGXXXXXXXXXXXX_P2_C3] attached to content generation
  -> Citation traceability audit, flag review, teacher approval remains required
```

**مهم:** البحث في الويب الموجود أصلًا في `web_research_engine.py` يظل مسارًا مكمّلًا منفصلًا؛ **لم تُدمج صفحات الويب تلقائيًا داخل الفهرس الدلالي** لأن ذلك يحتاج بروتوكول تحقق من الرخص والمصادر ومقاومة SSRF وسجل مراجعة الأستاذ. كذلك يعتمد مسار إنشاء مخطط مقرر كامل في `lesson_blueprint_engine.py` حاليًا على Evidence Bundle معتمد من المسار الأصلي. هذا الإصدار يربط RAG بمرحلة المحتوى وأقسام الدروس؛ **لا يدعي إنجاز توليد مقرر كامل انطلاقًا من PDF وحده**. هذه مهمة V0.3.

## 4) الإعدادات المناسبة للعمل أونلاين

على Windows PowerShell، بعد فتح مجلد المنصة وتثبيت `requirements.txt` وتوفير المفاتيح عبر Secrets بطريقة آمنة (لا تشاركي ملفها):

```powershell
$env:RAG_ENABLED="true"
$env:RAG_USE_LOCAL_EMBEDDINGS="false"
$env:RAG_CLOUD_EMBEDDINGS_ENABLED="true"    # اختياري - يتطلب Gemini + موافقة الأستاذ
$env:CONTENT_LLM_PROVIDER="groq"            # أو gemini، حسب الإعداد المتاح
$env:RAG_DB_PATH="C:\3alimnia-storage\rag_index.sqlite3"   # مسار تخزين مستمر يحدد وفق بيئتك
python -m streamlit run app.py
```

- لا حاجة لتثبيت Ollama، ولا `RAG_USE_LOCAL_EMBEDDINGS=true` في هذه المرحلة.
- للنشر عبر الإنترنت: `RAG_DB_PATH` يجب أن يشير إلى وحدة تخزين **مستمرة** يتوفر لها نسخ احتياطي وتشفير ومراقبة صلاحيات. خوادم Streamlit المجانية/عديمة الحالة قد تفقد ملفات SQLite عند إعادة التشغيل. الاستخدام متعدد المؤسسات أو متعدد الحاويات يحتاج PostgreSQL + pgvector أو بنية مشابهة قبل الإطلاق التجاري.
- مفتاح `GEMINI_API_KEY` ضروري فقط عند تفعيل الاسترجاع الدلالي عبر Gemini؛ البحث النصي FTS5 سيعمل بدونه. قم بتعيين مفاتيح Groq/Gemini كـSecrets خاصة في الخادم، **وليس داخل ZIP أو Git**.
- عند تفعيل embedding السحابي، سيرسل النظام نصوصًا من المرجع إلى Gemini **فقط** إذا وضع الأستاذ علامة الموافقة الخاصة بذلك المرجع. وسيستخدم استرجاعًا نصيًا فقط للوثائق الأخرى.
- الموافقة على *توليد الدروس عبر السحابة* مستقلة عن الموافقة على *embeddings*، لتجنّب نقل الملفات الحساسة ضمن طلبات التوليد دون تصريح.

## 5) التثبيت الآمن

1. احتفظي بنسخة من المجلد الأصلي وقاعدة البيانات والمفاتيح في مكان خاص، ثم فكّي حزمة PATCH في مجلد مستقل.
2. من المجلد الذي يحوي `apply_to_project.py`:

```powershell
python apply_to_project.py --target "C:\path\to\qai_platform_" --dry-run
python apply_to_project.py --target "C:\path\to\qai_platform_"
```

3. يمكن تثبيت الحزمة مباشرة على ZIP الأصلي بعد فكه، **أو** بعد V0.1، بشرط مطابقة بصمات الشيفرة المعتمدة. يرفض المثبت الملفات المتغيرة يدويًا، ويحفظ نسخة احتياطية من كل ملف شيفرة يكتب فوقه.
4. لا تتضمن الحزمة ملفات `.streamlit/secrets.toml`، قواعد بيانات المستخدمين، وثائق خاصة، `.git`، أو ملفات الأصول.
5. بعد التثبيت شغلي `python -m unittest tests.test_hybrid_rag_v01 tests.test_online_hybrid_rag_v02`.
6. اختبري بحساب أستاذ واحد ومقرر تجريبي واحد ومصدر PDF نصي واحد، أولًا في نمط lexical فقط، ثم (مع مصدر غير حساس) اختبري Gemini Embeddings الحقيقي.

- لم تُختبر واجهة Streamlit end-to-end أو مفاتيح فعلية من حساب الأستاذ، ولا جلسات متعددة حقيقية، ولا هجمات حقن تعليمات، ولا أداء تحميل 1000+ ملف.

## 7) التقييم العلمي القادم

نقارن أربع حالات بالمدخلات ونموذج التوليد نفسيهما إن أمكن:

- **A:** LLM دون استرجاع.
- **B:** Web research الموجود أصلًا.
- **C:** Hybrid RAG بدون حوكمة/ترتيب خاص بالمصدر (baseline مضبوط).
- **D:** مقترح 3alimnIA: أولوية الأستاذ، موافقات، مؤشرات مراجعة، وتوثيق على مستوى المقطع.

عند فحص الاسترجاع نستخدم Gold source relevance بعمل خبراء وليس الاستشهادات التي أنتجها النموذج. وعند فحص توليد الدروس نطلب تحكيمًا أعمى مستقلًا للحقيقة العلمية، دعم المصادر للادعاءات، التوافق التربوي، وزمن تعديل الأستاذ. لا تتجاوز هذه المرحلة إلى التجربة التعليمية مع الطلبة قبل إجراءات الموافقة المناسبة.

## 8) المهام العلمية والهندسية المؤجلة عمدًا

1. **V0.3 Evidence Bridge**: تحويل وثائق RAG المعتمدة إلى مسودة Evidence Bundle تدعم مخطط مقرر متكامل، مع مراجعة الأستاذ وعدم اختلاق مفاهيم أو مراجع.
2. **Claim-level entailment verification**: تصنيف الادعاء إلى supported / contradicted / insufficient اعتمادًا على الاستلزام الدلالي وخبرة بشرية، لا مجرد وجود Citation.
3. **External scholarly source workflow**: مصادر علمية معتمدة، بيانات DOI، تراخيص، عدم الزحف العشوائي للمواقع، تدقيق المصدر والإذن.
4. **Production security**: مراجعة وصول شامل، إدارة الأسرار، تشفير، retention/deletion, backups، والانتقال إلى تخزين متجهات وقاعدة متعددة المؤسسات.
5. **Scientific benchmark**: تسجيل تجارب متعددة المجالات واللغات مع معايرة المقيّمين والنشر المسموح للبيانات.

**تنبيه أمني:** النسخة الأصلية من المشروع ضمت `.streamlit/secrets.toml`. ينبغي تدوير أي أسرار حقيقية وردت فيها قبل مشاركتها أو رفع المشروع لخدمة استضافة عامة. هذا التحديث لا يعالج حذف الملف من نسختك الأصلية تلقائيًا.
