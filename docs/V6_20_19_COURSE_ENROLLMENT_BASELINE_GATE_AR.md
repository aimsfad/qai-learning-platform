# V6.20.19 — تسجيل المقرر والاختبار القبلي الخاص به

## لماذا هذا الإصدار؟

في V6.20.18 كان المقرر المنشور من الأستاذ يفتح Runtime التعلم مباشرة بعد اختيار المتعلم وتسجيل دخوله. وكان الاختبار القبلي الموجود في المنصة خاصًا بمسار الكوانتوم التجريبي العام، لذلك لا يصلح لفتح مقرر جديد مثل Python أو Machine Learning.

## السلوك الجديد

- يحتفظ المتعلم **بحساب واحد** في المنصة؛ لا يُنشئ حسابًا جديدًا لكل مقرر.
- عند اختيار مقرر جديد يُنشأ **تسجيل مستقل في ذلك المقرر**.
- لا تُفتح الدروس قبل إنجاز **اختبار قبلي خاص بالمقرر وإصداره المعتمد**.
- نتيجة اختبار مقرر آخر لا تفتح هذا المقرر.
- يبقى تسجيل المقرر مربوطًا بإصدار Blueprint المثبت عند بدء التسجيل.
- المقررات المستقبلية تطلب في Phase 8 حزمة JSON قابلة للقراءة آليًا لثلاثة أسئلة تشخيصية متعددة الخيارات.
- للمقررات القديمة التي لا يمكن استخراج أسئلتها آليًا، تستخدم المنصة خط أساس واضحًا لدرجة الألفة بالمفاهيم، وتوسمه صراحةً بأنه `self_report_baseline` بدل الادعاء بأنه اختبار موضوعي.

## رحلة المتعلم

`حساب المتعلم → التسجيل في المقرر → الاختبار القبلي للمقرر → التعلم`

## إصلاحات Glass UI المرافقة

- إصلاح الدائرة الزرقاء التي كانت تغطي عنوان Page Header.
- إزالة أثر Card-inside-Card من نسخة عنوان بطاقة مشروع الأستاذ.
- ضغط المسافات في منطقة مشروعات الأستاذ.
- إضافة شريط بصري واضح لمراحل التسجيل والاختبار القبلي.
